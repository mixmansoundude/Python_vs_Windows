# Messages of run_setup.bat that talk about building, packaging or verifying and are NOT about the standalone EXE (README REQ-007.20).
# Read by tools/exe_wording.py: `check` (tests/test_exe_wording.py, inside self.pytest.unit) holds every console message of
# run_setup.bat to the rule, and `console` (tests/selfapps_sysbuild_accept.ps1) holds every timestamped line of a real run to it.
#
# A rule for a message: when it says build, bundle, package or verify, it names the artifact or the tool in plain words
# (EXE, executable, standalone, PyInstaller, Nuitka), or its exact text is listed here under a category that says why it is
# about something else. Reword first; list a message only when a reword would make it false or untrue to its subject.
#
# An entry reads "<category> | <message text as run_setup.bat writes it>". Whitespace is collapsed, ^ escapes and *** banners are
# dropped, a %VARIABLE% stays as written (the console check lets it match any text), and a block of consecutive echo lines is one
# message. The list can only shrink or be re-decided on purpose: an entry that no console message of run_setup.bat reads any more,
# or that the message no longer needs (it now names the EXE), turns the unit test red until its line is removed.

category: usage | the first argument was refused before any provider, dependency or EXE work started, so build only says nothing was started
category: environment | the message is about rebuilding the conda environment, not about the EXE
category: interpreter | the message says the check is made through the Python interpreter, which is the verification when no EXE exists
category: provider | the message is about moving to another Python provider or keeping the current one; the build it keeps can be the EXE or an interpreter-only run
category: embed | the message is about downloading and verifying the embedded Python, which is a Python provider, not the EXE
category: exit_code | the line only reports the exit code of a verification run that another line announces by naming the EXE or the interpreter
category: program | the message is about the user's own program, a second run of it or the packages it asked for, not about the EXE
category: diagnostic | a bookkeeping line about a breadcrumb file, not a statement about the EXE
category: prompt | a one-line question that sits directly under a block which names the standalone EXE and is held to the rule on its own
